# ROS 2 Humble — Orange Pi 5 Plus (RK3588) Project Rules

Autonomous 3D LiDAR SLAM and Navigation simulation project on an ARM64 (aarch64) Single Board Computer. Every decision, compilation, and code generation must respect the hardware limits and software architectures specified below.

## 1. System & Hardware Environment
- **Platform**: Orange Pi 5 Plus (SBC)
- **SoC**: Rockchip RK3588 (8-Core: 4× Cortex-A76, 4× Cortex-A55)
- **RAM**: 16 GB (No swap required for compilation, but thread safety is critical)
- **OS**: Ubuntu 22.04 LTS (Jammy Jellyfish)
- **ROS 2 Version**: ROS 2 Humble Hawksbill
- **DDS Middleware**: **Eclipse CycloneDDS** — Always export before any ROS 2 command:
  ```bash
  export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
  ```
- **Simulation Engine**: **Ignition Fortress** (Gazebo Sim 6.x) via `ros_gz` bridge — SDF 1.8

## 2. Compilation Rules (colcon)
Always adhere to these compiler constraints to prevent Orange Pi system lockups:
- **Build Command**: Always run from `~/ros2_ws`:
  ```bash
  colcon build --symlink-install
  ```
- **Thread Control**: Hard-limit make threads to RK3588's 8 physical cores:
  ```bash
  export MAKEFLAGS="-j 8"
  ```
- **C++ Optimization (NEON)**: For C++ code (especially FAST-LIO matrix operations):
  ```
  -O3 -march=armv8-a+crypto -mcpu=cortex-a76
  ```

## 3. Ignition Fortress Simulation (SDF 1.8)

### Headless Mode (Production Command)
```bash
export LIBGL_ALWAYS_SOFTWARE=1
xvfb-run -a ros2 launch outdoor_sim sim_launch.py
```
- `LIBGL_ALWAYS_SOFTWARE=1` — Force software rendering; avoids Mali-G610 GPU driver deadlocks on RK3588.
- `xvfb-run -a` — Virtual X display for the ogre2 render engine in headless mode.
- The launch file passes `-s -r` to `gz sim` (`-s` = server-only, `-r` = unpause on start).

### World File Requirements
- **Format**: Ignition SDF **1.8** (`<sdf version="1.8">`)
- **4 Mandatory System Plugins**:
  1. `gz::sim::systems::Physics`      — `ignition-gazebo-physics-system`
  2. `gz::sim::systems::Sensors`      — `ignition-gazebo-sensors-system` (`<render_engine>ogre2</render_engine>`)
  3. `gz::sim::systems::SceneBroadcaster` — `ignition-gazebo-scene-broadcaster-system`
  4. `gz::sim::systems::UserCommands` — `ignition-gazebo-user-commands-system`
- **Physics**: DART engine at 200 Hz (`<max_step_size>0.005</max_step_size>`).
- **❌ Heightmap**: NEVER use `<heightmap>`. It causes Ogre shader segfault (exit code -11) on ARM64 Mali GPUs. Use flat `<box>` ground_plane + 3D primitives (boxes, cylinders, walls).

### Sensor Placement (Ignition Convention)
- Sensors go **INSIDE** `<link>` elements as `<sensor type="...">` children — NOT in `<gazebo>` extension blocks.
- Every sensor MUST have `<ignition_frame_id>link_name</ignition_frame_id>`.
- Every sensor MUST have `<topic>` (the Ignition-internal topic name).

## 4. Sensor Specifications — DJI Mid-360 Equivalent

### LiDAR (gpu_lidar → CPU Ray)
| Parameter | Value |
|-----------|-------|
| Sensor type | `<sensor type="gpu_lidar">` with `<lidar>` wrapper |
| Horizontal FOV | **360°** (−π to +π) |
| Vertical FOV | **59°** (−0.5149 to +0.5149 rad → ±29.5°) |
| Lines (vertical samples) | **64** (high-density Mid-360 equivalent) |
| Horizontal samples | 900 per ring |
| Range | 0.1 m – 40.0 m (Mid-360 blind-zone-free minimum) |
| Update rate | 10 Hz |
| Ignition topic | `/lidar/points/points` (auto-generated by gpu_lidar sensor) |
| ROS 2 topic | `/velodyne_points` (via `ros_gz_bridge` remap) |

### IMU
| Parameter | Value |
|-----------|-------|
| Sensor type | `<sensor type="imu">` with `<imu>` wrapper |
| Update rate | **200 Hz** (mandatory for FAST-LIO stability) |
| Noise model | 6-axis Gaussian (angular_velocity x/y/z + linear_acceleration x/y/z) |
| Ignition topic | `/imu/data` |
| ROS 2 topic | `/imu/data` |

### TF Tree
```
base_link
├── lidar_link   (fixed joint, z=0.1)
└── imu_link     (fixed joint, z=0.1)
```
Always verify clean TF chains in RViz2 before launching SLAM.

## 5. Communication Bridge (`ros_gz_bridge parameter_bridge`)

Bridge syntax: `<topic>@<ROS_type>[<Ignition_type>` — `[` = Ignition→ROS one-way.

```bash
/clock@rosgraph_msgs/msg/Clock[ignition.msgs.Clock
/lidar/points@sensor_msgs/msg/PointCloud2[ignition.msgs.PointCloudPacked
/imu/data@sensor_msgs/msg/Imu[ignition.msgs.IMU
```

Remap in launch file: `/lidar/points` → `/velodyne_points`.

## 6. ROS 2 Launch Rules (Humble)
- **Xacro loading**: Always wrap with `ParameterValue(..., value_type=str)` to prevent YAML parser crashes on XML syntax.
- **Robot spawn**: Use `ros_gz_sim create` (NOT the deprecated `gazebo_ros spawn_entity.py`):
  ```bash
  ros2 run ros_gz_sim create -name outdoor_bot -topic robot_description -x 0.0 -y 0.0 -z 0.5
  ```
