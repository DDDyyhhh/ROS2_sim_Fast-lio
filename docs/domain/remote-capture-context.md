# 遥控采集与覆盖任务上下文

本上下文定义机器人通过遥控采集作业边界、禁区和跨区通道时使用的领域语言。它与现有旧版区域 YAML 和 `/web/areas` 兼容层并存，但新模型不再把不同对象混成同一种区域。

## 任务对象

**作业对象（Mission object）**：任务中被定义、采集、校验和持久化的一个对象，类型只能是作业区、禁区或连接通道。
_避免_：区域（它只描述几何形状，不说明对象类型）

**作业区（Work area）**：一个闭合多边形，机器人在其中进行覆盖作业，覆盖率只统计作业区内部。
_避免_：区域、割草区域（在需要区分对象类型时）

**禁区（No-go zone）**：一个全局生效的闭合多边形，机器人不得进入；它同时约束所有作业区和连接通道。
_避免_：障碍物、内岛（这两个词只描述旧实现或物理障碍，不代表新领域对象）

**连接通道（Corridor）**：一条开放的中心线及其通行宽度，用于连接两个作业区；通道只负责通行，不计入覆盖率。
_避免_：区域间直线、过渡线（除非明确指旧版实现）

**对象空间关系**：作业区的原始边界可以包含禁区；有效覆盖几何等于作业区扣除全部全局禁区。禁区可以彼此重叠并整体约束；通道中心线及其通行包络不得穿过禁区；作业区之间不得有面积重叠但可以边界相接；通道必须连接两个作业区。
_避免_：把“原始边界包含禁区”和“覆盖路径进入禁区”当成同一件事

**执行顺序（Execution order）**：多个作业区的默认顺序来自采集顺序；确认一个连接通道时，如果它引用的两个作业区在当前顺序中相邻，通道自动插入两者之间。端点缺失或不相邻时不重排既有作业，规划校验必须 fail-closed；禁区是全局约束，不进入执行顺序。
_避免_：固定采集顺序

**采集任务（Capture task）**：一次只记录一个作业对象（作业区、禁区或连接通道）的操作流程；采集完成后必须经过确认，才会成为任务数据。
_避免_：绘图、一次提交（它们是 UI 或通信动作，不是领域对象）

**采集草稿（Capture draft）**：采集过程中或定位健康不足时保存的未确认对象；草稿可以继续编辑，但不能进入规划或执行。
_避免_：有效任务、已确认对象

## 采集数据

**原始轨迹（Raw trajectory）**：采集过程中按时间记录的机器人位姿序列，保留坐标系、时间和定位来源信息；它不是可直接执行的覆盖路径。
_避免_：GPS 轨迹、路径（浏览器 GPS 不能替代机器人位姿，规划路径也不是采集轨迹）

**有效几何（Effective geometry）**：由原始轨迹派生、经过闭合和几何校验、可供任务使用的作业区边界、禁区边界或通道中心线；它与原始轨迹同时保存，不能覆盖原始数据。
_避免_：原始轨迹、规划路径

**有效覆盖几何（Effective coverage geometry）**：从作业区有效边界中扣除全部全局禁区后的可覆盖几何；它决定覆盖范围，不改变作业区原始边界或禁区本身。
_避免_：原始作业区、障碍物内岛

**任务坐标系（Map frame）**：保存作业对象几何和原始轨迹的全局坐标系；正式采集优先使用融合定位提供的 `map` 位姿，简化仿真才允许回退到局部里程计。
_避免_：浏览器坐标、经纬度坐标（它们只能作为输入或显示坐标）

**覆盖段（Coverage segment）**：规划后位于作业区内、计入覆盖率的路径段。
_避免_：路径（“路径”未区分覆盖和通行）

**通行段（Transit segment）**：规划后用于在对象之间移动、但不计入覆盖率的路径段；连接通道对应通行段。
_避免_：覆盖路径

## 待确认术语

闭合容差的具体数值、轨迹简化容差、真实机器人包络尺寸和安全余量尚未确认；实现前必须单独定义。
