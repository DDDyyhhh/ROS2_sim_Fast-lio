# 遥控采集作业区、禁区与跨区通道计划

领域术语和空间规则见：[遥控采集与覆盖任务上下文](domain/remote-capture-context.md)。

## 目标与首版边界

- 保留现有地图绘制作为备用和修正入口，新增响应式 Web 遥控采集向导。
- 将任务拆成“作业区、禁区、连接通道”三类对象，后端以机器人 ROS 位姿记录轨迹。
- 首版定位异常默认停车；Mid360 仅作为未来受限降级运行依据，不直接替代全局定位。
- 真实 Mid360、割刀包络和 CAN 控制链尚未完成，首版先在仿真中验收。

## 产品与数据模型

- `work_areas`：闭合作业区边界。
- `no_go_zones`：闭合禁区边界。
- `corridors`：开放中心线、起止区域、通道宽度、双向标志。
- 按采集顺序保存并执行多个作业区；确认通道时，若其起止作业区当前相邻，则自动插入两区之间；通道只通行、不计入覆盖率。
- 保存原始轨迹、采集来源、机器人包络和安全余量；有效几何由统一规则生成。
- 外边界向内收缩，禁区向外膨胀，通道宽度至少容纳机器人包络和安全余量；避免与现有障碍膨胀重复计算。
- 兼容现有 `/web/areas` 和旧 YAML；旧地图任务自动转换为新模型。

## 控制、定位与 ROS 接口

- `/teleop/cmd_vel`：网页遥控输入；`/cmd_vel` 由控制仲裁器唯一发布。
- `/mission/capture/command`：开始、暂停、完成、取消、撤销采集，以及删除指定任务对象。
- `/mission/capture/state`：采集状态、对象类型、点数、定位状态和错误。
- `/mission/capture/drive_allowed`：位姿新鲜且定位健康时允许仿真移动；不依赖是否正在采集。
- `sampling_allowed`：状态消息字段；仅 `capturing/draft` 会记录原始轨迹。
- `/mission/capture/raw_path`：当前原始轨迹。
- `/localization/health`：定位健康状态。
- `/coverage/path_metadata`：覆盖段与跨区通行段元数据。
- 遥控采用按住才运动；松手、网页断开、命令超时、定位失效或自动任务启动时立即停车。
- 完整模式优先使用 `/odometry/filtered`，简化仿真回退 `/odom`；不使用浏览器 GPS 轨迹作为最终采集数据。

## 定位降级策略

- `GREEN`：融合位姿、Mid360/FAST-LIO、IMU、点云时间和消息新鲜度正常，可采集和执行。
- `YELLOW`：例如 RTK 失效但 Mid360 局部里程计仍连续；首版仍停车，不允许新采集、跨通道或继续贴近禁区。
- `RED`：Mid360 匹配退化、位姿跳变/超时、协方差异常、点云异常或融合发散，立即停车。
- 后续如开放 `YELLOW` 降级运行，必须增加时间/距离上限、低速限制、漂移检测和现场标定。

## 实施顺序与验收

1. 增加任务模型、几何补偿、任务校验和旧格式兼容层。
2. 增加定位健康监测、遥控控制仲裁和仿真启动配置。
3. 改造 Web 为移动端响应式采集向导，支持实时轨迹、确认、撤销和修正。
4. 改造规划器使用已记录通道，不再对跨区连接默认使用直线。
5. 改造执行器接收路径元数据，并保持现有地图绘制流程可用。
6. 用仿真故障注入验证 RTK 丢失、Mid360 失效、断网、松手和自动停车。
7. 未完成真实尺寸测量和 CAN 安全审查前，不在实机上发送运动控制帧。

开发阶段继续维护根目录 `implementation-notes.md` 的 Deviations、Discovered edge cases、Verification evidence 和底部 Active Handoff。
