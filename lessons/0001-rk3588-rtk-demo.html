RK3588 RTK 领导演示

用 5–10 分钟展示 CORS 差分数据进入 UM982、接收机达到 RTK Fixed、ROS 判断全局定位可信，同时明确机器人没有运动。

安全边界：电机电源关闭、急停有效；不启动 CAN、规划器、执行器或 /cmd_vel。

一、演示前检查

  1. 蘑菇头固定在户外开阔位置，测试期间不要移动。
  2. 账号密码只保存在 RK3588 私有 ~/mower_ws/deploy/rk3588/.env，不要投屏。
  3. 确认没有第二个串口 owner：
ssh rk3588 && cd ~/mower_ws/deploy/rk3588 && docker compose config -q && echo CONFIG_OK
pgrep -af 'str2str|nmea_serial|rtk_ntrip' || true
readlink -f /dev/serial/by-id/usb-Prolific_Technology_Inc._USB-Serial_Controller_DPBNb152808-if00-port0

二、启动正式演示

cd ~/mower_ws/deploy/rk3588 && docker compose up -d --no-build --force-recreate mower_rtk && docker compose ps

看到 mower-rkt Up 后打开三个窗口：

窗口 A：启动过程

docker compose logs -f --tail=30 mower_rtk

等待日志出现：serial=CONNECTED → ntrip=CONNECTED → RTK_FIXED。

窗口 B：机器可读状态

docker exec mower-rkt bash -lc 'source /opt/ros/humble/setup.bash && source /opt/mower_ws/install/setup.bash && ros2 topic echo /rtk/status --once --field data'
字段含义
solution=RTK_FIXEDUM982 当前为固定解。
quality=4原始 GGA 的 RTK Fixed 标志。
ntrip=CONNECTED已连接 CORS caster。
corrections_fresh=true最近 15 秒确实收到 RTCM。
global_position_trusted=true系统允许把当前 RTK 当作全局定位依据。
invalid_gga=0GGA 校验正常。

窗口 C：频率和坐标

docker exec mower-rkt bash -lc 'source /opt/ros/humble/setup.bash && source /opt/mower_ws/install/setup.bash && ros2 topic hz /gps/fix --window 5'
docker exec mower-rkt bash -lc 'source /opt/ros/humble/setup.bash && source /opt/mower_ws/install/setup.bash && ros2 topic echo /gps/fix --once'

正常频率约 1 Hz。坐标用于展示位置，RTK 类型以窗口 B 的 /rtk/status 为准。

三、推荐话术

“这里不是只读到了 GPS 坐标。”

“CORS 通过 NTRIP 提供 RTCM 差分数据，UM982 接收并计算固定解。单一节点独占串口，同时读取 NMEA、写入 RTCM，并单独发布 RTK 状态。”

“只有串口正常、GGA 新鲜、quality=4、CORS 已连接且最近收到 RTCM，global_position_trusted 才为 true。”

三点五、展示已完成的 300 秒验收

先展示300 秒静态验收结果，再展示 RK3588 当前的 /rtk/status。最新一轮 300/300 条为 RTK_FIXED；Fixed-only 样本东西向标准差约 8 mm、南北向约 10 mm。这里的标准差表示固定解短时重复性，不是绝对定位误差。

四、领导可能追问

问题回答
为什么不是一有坐标就可信？普通单点定位也有坐标，但不能保证厘米级全局位置；必须同时满足解状态和差分新鲜度。
断网会不会继续乱跑？RTCM 超过 15 秒不更新会撤销全局信任；当前 profile 不发运动命令。
USB 拔插会不会必须固定 ttyUSB0？不会，系统使用 by-id 稳定路径。
这次有没有让机器动？没有，CAN、规划器、执行器和 /cmd_vel 都没有启动。

五、不要临时做的事

  • 不要同时启动 str2str 和 ROS 节点。
  • 不要把 `.env`、密码或完整环境变量投屏。
  • 不要为了展示断流关闭 RK3588 Wi-Fi；断流恢复测试已经单独完成。
  • 不要在本次演示里启动 CAN 或电机。
